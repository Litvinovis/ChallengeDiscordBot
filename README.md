# Sport Challenge Bot

Discord бот для создания и отслеживания спортивных челленджей — например, "10 000 отжиманий до конца года".

## Описание

Sport Challenge Bot позволяет организовывать индивидуальные и групповые спортивные испытания прямо в Discord. Участники записывают свой прогресс простыми командами в канале, бот считает суммарный результат, ведёт таблицы лидеров и каждое утро в 7:00 присылает отчёт с топ-3 участниками по каждому испытанию — но только если за сутки кто-то вносил прогресс.

## Технологии

- Java 25
- Spring Boot 4.1
- PostgreSQL 16 (хранение данных через Spring JDBC / JdbcTemplate)
- JDA 6.5 (Java Discord API)
- Maven (система сборки)

## Установка и запуск

### Требования

- Java 25 или выше
- PostgreSQL 16+

### Сборка проекта

```bash
mvn clean package
```

### Настройка конфигурации

Бот читает чувствительные параметры из переменных окружения. На сервере конфигурация хранится в `/opt/challengeBot/config/application.yml` (этот файл не коммитится в репозиторий).

Основные переменные:

| Переменная | Описание |
|---|---|
| `DISCORD_BOT_TOKEN` | Токен бота с портала разработчиков Discord |
| `DISCORD_CHANNEL_ID_1` | ID основного канала для команд |
| `DISCORD_CHANNEL_ID_2` | ID дополнительного канала (опционально) |
| `DISCORD_REPORT_GUILD_ID` | ID сервера Discord для ежедневных отчётов |
| `DISCORD_ADMIN_USER_ID` | ID пользователя-администратора |
| `DB_URL` | JDBC URL базы данных (например: `jdbc:postgresql://127.0.0.1:5432/challengebot`) |
| `DB_USER` | Имя пользователя PostgreSQL |
| `DB_PASSWORD` | Пароль пользователя PostgreSQL |

### Запуск приложения

```bash
java -jar target/challenge-bot-1.0.1.jar
```

Схема БД создаётся автоматически при первом запуске (`schema.sql`).

## Команды бота

### Основные команды

- `+<испытание> <количество>` - Добавить прогресс к испытанию (например: `+отжимания 10`); отрицательное число уменьшает прогресс
- `+статистика [испытание]` - Статистика по всем или конкретному испытанию: прогресс, топ-3, стрик-лидер, сравнение недель, лучший день
- `+испытания` - Список всех активных испытаний
- `+помощь` - Показать справку по командам

### Команды управления испытаниями (только для администраторов)

- `+новый <название> <цель> [дата окончания] [тип]` - Создать новое испытание (дата: `dd.MM.yyyy` или `yyyy-MM-dd`)
- `+удалить <название>` - Удалить испытание
- `+остановить <название>` / `+продолжить <название>` - Приостановить/возобновить испытание
- `+изменить <название> <новая цель>` - Изменить цель испытания
- `+изменить_дату <название> <новая дата>` - Изменить дату окончания испытания
- `+установить_прогресс <испытание> <пользователь> <количество>` - Установить прогресс участника
- `+добавить_участника <испытание> <пользователь>` / `+удалить_участника <испытание> <пользователь>` - Управление участниками
- `+бэкап` - Экспорт всех испытаний и прогресса в JSON-файл
- `+импорт` - Импорт испытаний и прогресса из прикреплённого JSON-бэкапа

### Команды пользователя

- `+мои` - Показать личные испытания
- `+детали <испытание>` - Личная детализация прогресса за 30 дней
- `+топ <испытание> [количество]` - Таблица лидеров по испытанию
- `+топ-день <испытание>` - Лидеры за последние 24 часа
- `+прогресс <испытание>` - Личный прогресс по испытанию
- `+прогноз <испытание>` - Прогноз даты завершения при текущем темпе (среднее за 7 дней)
- `+график <испытание>` - PNG-график личного прогресса
- `+динамика <испытание>` - PNG-график динамики испытания за 30 дней
- `+участие <испытание>` - PNG-диаграмма вкладов участников
- `+экспорт <испытание>` - Выгрузка прогресса в CSV
- `+регистрация <название>` - Зарегистрироваться на испытание
- `+обновить_имя [новое имя]` - Обновить своё имя в системе

## Функции

- Создание индивидуальных и групповых испытаний
- Отслеживание прогресса участников (атомарные обновления в PostgreSQL)
- Ежедневные (7:00, только при наличии прогресса за сутки), еженедельные (вс 20:00) и ежемесячные отчёты с топ-3 и прогресс-баром
- Достижения (100/500/1000/5000 повторений) и стрики активности (3/7/30 дней) с поздравлениями в канале
- Уведомление при достижении 50% цели и автоматическое закрытие испытаний (по цели или сроку)
- Прогноз даты завершения по среднему темпу за 7 дней из истории прогресса
- PNG-графики (JFreeChart): личный прогресс, динамика, вклад участников
- Экспорт CSV, JSON-бэкап/импорт
- Архивация завершённых испытаний старше 30 дней
- Названия испытаний из нескольких слов — в кавычках: `+новый "бег утром" 1000`, работает во всех командах
- Система прав доступа (администратор/пользователь)
- Все расчёты дат — в едином часовом поясе Europe/Moscow

## Архитектура

### Компоненты

1. **Discord Client** - Платформа Discord, где пользователи взаимодействуют с ботом
2. **Discord Bot Application** - Основное Spring Boot приложение
3. **Message Handler** - Компонент, прослушивающий сообщения в назначенном канале
4. **Command Processor** - Анализирует и направляет команды соответствующим сервисам
5. **Challenge Service** - Управляет созданием, изменением и отслеживанием испытаний
6. **Statistics Service** - Генерирует статистику и отчеты о прогрессе
7. **PostgreSQL Data Store** - База данных для хранения испытаний, участников и прогресса
8. **Scheduled Tasks** - Запланированные задачи для ежедневных отчетов

### Модели данных

1. **Challenge** - Модель испытания
2. **Participant** - Модель участника
3. **ProgressRecord** - Запись истории прогресса (challenge_id, user_id, объём, время)
4. **ChallengeType** - Тип испытания (индивидуальное/групповое)

## Деплой через GitHub Actions

Проект настроен на автоматический деплой при пуше в ветку `main`.

### Как устроен пайплайн

Файл: [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml)

1. **Checkout** — клонирует репозиторий на self-hosted runner.
2. **Build & Test** — собирает проект и прогоняет тесты: `mvn package -B`.
3. **Deploy** — копирует собранный `.jar` в `/opt/challengeBot/`, делает резервную копию предыдущей версии и перезапускает systemd-сервис `bot-challenge`.
4. **Smoke test** — проверяет, что сервис поднялся; в случае неудачи автоматически восстанавливает резервную копию.
5. **Notify Telegram** — отправляет уведомление в Telegram о результате деплоя (успех / ошибка).

### Необходимые GitHub Secrets

| Secret | Описание |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен Telegram-бота для уведомлений |
| `TELEGRAM_CHAT_ID` | ID чата для отправки уведомлений |

> Токен Discord бота, ID каналов и параметры БД хранятся в `config/application.yml` на сервере (`/opt/challengeBot/config/application.yml`) — они не передаются через GitHub Secrets.

### Ручной запуск деплоя

Деплой можно запустить вручную через вкладку **Actions** → **Build & Deploy — Challenge Bot** → **Run workflow**.

### Структура директории на сервере

```
/opt/challengeBot/
├── challenge-bot-<версия>.jar     # Текущий jar-файл (юнит ищет его по маске)
├── config/
│   ├── application.yml           # Конфиг с реальными значениями (не в git)
│   └── logback.xml               # Конфиг логирования
└── logs/
    ├── challengebot.log
    ├── challengebot-error.log
    └── challengebot-warn.log
```

### Управление сервисом на сервере

```bash
sudo systemctl start bot-challenge
sudo systemctl stop bot-challenge
sudo systemctl restart bot-challenge
sudo systemctl status bot-challenge
```

Юнит `bot-challenge.service` запускает jar по маске `challenge-bot-*.jar`, поэтому
смена версии в `pom.xml` не требует правки юнита.
